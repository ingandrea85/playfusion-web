# Runbook — S0.14: first stg deploy + pilot E2E on real AWS

Deploys the ADR-002 topology (S0.6–S0.10) to **collaudo** (`stg`) on real AWS and runs the
pilot acceptance E2E against it. Closes the ADR-010 "deployed SFN" open item.

> **This is a user action.** It needs a real AWS account and credentials, so it cannot run
> in the sandboxed dev environment. Everything it depends on is already in the repo; this
> runbook is the procedure + the evidence template.

## Prerequisites

1. The OIDC deploy role is bootstrapped — see [`infra/bootstrap/README.md`](../../infra/bootstrap/README.md) (S0.13),
   including `cdk bootstrap aws://<ACCOUNT_ID>/eu-south-1`.
2. Repo variable `AWS_DEPLOY_ROLE_ARN` is set.

## Deploy to stg

**Option A — via CI (preferred):** create/push the `stage` branch; `deploy-stage.yml` (S0.11)
deploys `stg`.
```bash
git switch -c stage main && git push -u origin stage
```

**Option B — locally**, with credentials for the account:
```bash
cd infra/cdk
npm run build -w @playfusion/platform-lib   # (from repo root) bundle dep
npx cdk deploy --all -c env=stg --require-approval never
```

Record the API Gateway base URL from the `playfusion2-api-stg` stack outputs, e.g.
`https://<id>.execute-api.eu-south-1.amazonaws.com/prod`.

## Run the pilot E2E against real AWS

```bash
API_BASE_URL="https://<id>.execute-api.eu-south-1.amazonaws.com/prod" npm run test:e2e
```

`test/e2e/pilot-e2e.e2e.test.ts` drives the deployed API (apply→confirm, apply→reject).
For the full EventBridge / PB-1 criteria, run the integration suite with the AWS SDK
pointed at real AWS (unset `AWS_ENDPOINT_URL`, real creds, `PF_ENV=stg`).

**Three latent defects fixed to reach green** (see commit `a8014f2`): (1) ESM bundle —
pino dynamic `require('node:os')` crashed every Lambda at init → `createRequire` banner;
(2) routing — API Gateway `/<bc>/{proxy+}` full path vs unprefixed Hono routes → strip the
mount prefix at the Lambda boundary; (3) authorization — `O2_BASE_URL` defaulted to
LocalStack → inject the deployed o2 route URL.

**Criteria 3 & 5 verified on real AWS (2026-08-01):**
- **3** — a temporary EventBridge rule (`source: playfusion2`) → SQS tap on `playfusion2-bus-stg`;
  driving `POST /o3/events` published `EventPublished`, captured off the real bus with the full
  envelope (`eventId`, `organizationId`, `occurredAt`, `correlationId`). Tap torn down after.
- **5** — the **deployed** SFN (not the L2 orchestrator) was made to drive the real API: ASL
  paths BC-prefixed, `$.apiHost`+`$.stage` endpoint contract, and `x-approver-token` header
  (apigateway:invoke forbids the reserved `authorization` header — `States.Runtime`, uncatchable).
  A driver started the execution and serviced both task-token Activities (apply via O5 / pay via
  O12 with a real O2 magic-link token); it walked CreateEvent → OpenRegistrationWindow →
  WaitForApplication → ConfirmTeam(**Confirmed**) → WaitForFeePaid(**Paid**) → SetupComplete =
  **SUCCEEDED**. Code under test: commit `9218ee0`.
