# S0.1 — Monorepo workspace scaffold (apps/libs/services/infra)

- **Date:** 2026-07-28
- **Slice:** S0 — Monorepo + deploy foundation
- **Issue:** [ingandrea85/playfusion-web#1](https://github.com/ingandrea85/playfusion-web/issues/1)
- **ADR:** ADR-011 (Unified 2.0 Monorepo), ADR-012 (Deploy CDK + GitHub Actions)
- **Branch:** `feature/s0.1-monorepo-scaffold`

## Goal

Repurpose `playfusion-web` from the mockup repo it is today into the ADR-011
2.0 monorepo **skeleton**: `apps/` (Experience SPAs), `libs/` (PS-B + rest-client),
`services/` (Bounded Contexts), `infra/` (CDK). The workspace tool is **Nx layered on
top of npm package-manager workspaces** — Nx provides the task graph, caching and native
module-boundary enforcement, while npm workspaces remain the package manager so the
pilot's packages (also npm workspaces) migrate cleanly in S0.2.

### Acceptance criteria (from the issue)

- Root `npm install` resolves **all** workspaces.
- Empty `build` and `test` run **end-to-end** (`nx run-many -t build` / `-t test` exit 0).

S0.1 delivers **structure only**. No real Bounded Context, PS-B component, or CDK
resource is created here — those arrive in later S0 issues.

## Design

### 1. Relocate the mockups (behaviour unchanged)

The repo currently holds mid-fidelity mockups (fake `localStorage` state) wired to a
single root Vite/Vitest. The whole mockup tree moves **as one unit** into `mockups/` via
`git mv`, so every relative path inside it stays valid:

```
mockups/
  index.html                       # the hub
  apps/{organizer,public,admin,account}/*.html + *.ts
  shared/                          # mock domain logic, tokens.css, ui.css, chrome.ts
  vite.config.ts                   # __dirname now = mockups/, its apps/*.html inputs stay valid
  vitest.config.ts
  tsconfig.json
  README.md                        # the mockup README
  package.json                     # becomes @playfusion/mockups (private)
```

`mockups/` is a workspace package (`@playfusion/mockups`, `private: true`) carrying its
current runtime deps (`@fontsource-variable/*`) and dev deps (`vite`, `vitest`, `jsdom`,
`typescript`). It stays runnable and its existing unit tests keep passing **in place** —
no source or test file inside the mockups is edited, only moved.

Mockups are intentionally **not** part of the Nx project graph for apps/libs/services/infra
(they are reference material, not a product package). They are reached through the package
manager and a dedicated npm script.

### 2. New repo root (Nx + npm workspaces)

Files created at the repo root:

- **`package.json`**
  - `"workspaces": ["apps/*", "libs/*", "services/*", "infra/*", "mockups"]`
  - devDeps: `nx`, `@nx/js`, `@nx/vite`, `@nx/eslint`, `typescript`, `vitest`,
    `eslint`, `typescript-eslint`, `@types/node`.
  - scripts:
    - `build` → `nx run-many -t build`
    - `test` → `nx run-many -t test`
    - `lint` → `nx run-many -t lint`
    - `mockups` → serve the mockups (`npm run dev -w @playfusion/mockups`)
  - `engines.node`: `>=20 <21` (kept from today; matches devcontainer + pilot).
- **`nx.json`** — plugins (`@nx/js/typescript`, `@nx/vite`, `@nx/eslint`), `targetDefaults`
  with caching for `build`/`test`/`lint`, and `namedInputs` for cache correctness.
- **`tsconfig.base.json`** — shared compiler options mirroring the pilot (ES2022 target,
  `strict`, bundler module resolution, `skipLibCheck`) plus `paths` for `@playfusion/*`
  aliases so packages import each other by name.
- **`eslint.config.js`** — ESLint 9 flat config wiring **`@nx/enforce-module-boundaries`**.
  This rule *is* the ADR-011 "no-cross-BC" boundary expressed natively in Nx. Each package
  is tagged with `scope:<layer>` (`app`/`lib`/`service`/`infra`) and `type:*`; the rule
  forbids disallowed edges (e.g. `service → service`, `app → service`, `infra → app`).
- **`.gitignore`** — extend with `.nx/` and `tmp/`.
- **`.nvmrc`** — `20` (currently empty; align with pilot).

### 3. One placeholder package per layer

To make the acceptance real — a non-empty graph where `build`/`test` actually execute —
each layer gets a single trivial package that is deleted as real content lands:

```
apps/_placeholder/        # @playfusion/app-placeholder,     tag scope:app
libs/_placeholder/        # @playfusion/lib-placeholder,     tag scope:lib
services/_placeholder/    # @playfusion/service-placeholder, tag scope:service
infra/_placeholder/       # @playfusion/infra-placeholder,   tag scope:infra
```

Each placeholder contains:
- `package.json` (`private: true`, name `@playfusion/<layer>-placeholder`).
- `tsconfig.json` extending `../../tsconfig.base.json`.
- one trivial source module (e.g. `export const placeholder = '<layer>' as const`).
- one passing Vitest test asserting that value.
- `build` (tsc) and `test` (vitest) targets, correct Nx tags.
- a top-of-file comment stating the package is a temporary S0.1 scaffold to be removed
  when the real layer content arrives (S0.2 services, S0.5 libs, S0.6+ infra, S6+ apps).

### 4. Devcontainer

`.devcontainer/devcontainer.json`, mirroring the pilot but trimmed to front-end needs:

- image `mcr.microsoft.com/devcontainers/typescript-node:20` (matches `engines`).
- `forwardPorts: [5173]` (Vite default).
- `postCreateCommand: "npm install"` (resolves all workspaces on create).
- VS Code extensions: `dbaeumer.vscode-eslint`, `vitest.explorer`, `nrwl.angular-console`
  (Nx Console).
- **No** `docker-outside-of-docker` feature yet (front-end only at S0.1). A comment notes
  it is added in S0.6+ when LocalStack/services arrive.

### 5. VS Code tasks + launch

`.vscode/tasks.json`:

- **`Front-end: serve`** — default build task, `isBackground: true`, Vite problem matcher →
  `npm run mockups`. This is the runnable front-end *today* (the mockups); real Experience
  SPAs add their own serve tasks here from S6 on.
- **`Build all`** → `npm run build`.
- **`Test all`** → `npm run test`.
- **`Lint all`** → `npm run lint`.

`.vscode/launch.json`:

- a Chrome launch configuration pointing at `http://localhost:5173` so F5 opens the served
  front-end.

Both `.vscode/` and `.devcontainer/` are committed (shared dev config, not machine-local).

## Out of scope for S0.1

- Migrating real Bounded Contexts from the pilot into `services/*` — **S0.2**.
- Renaming resources/config to `playfusion2-*` + env token — **S0.3**.
- Any standalone lint rule beyond the Nx boundary config — **S0.4** (largely subsumed by
  `@nx/enforce-module-boundaries`).
- PS-B (`libs/tokens`, `libs/ui`) migration from `playfusion-frontend` — **S0.5**.
- All CDK / infra content (DynamoDB, EventBridge, Lambda, API Gateway, Step Functions,
  S3+CloudFront) — **S0.6 … S0.10**.
- GitHub Actions CI + AWS OIDC role — **S0.11 … S0.14**.

## Risks & decisions

- **Assemble Nx manually, not via `create-nx-workspace`.** That generator wants an empty
  directory and would clobber git history and the relocated mockups. We write `nx.json` /
  `tsconfig.base.json` / `eslint.config.js` by hand into the existing repo.
- **Nx + npm workspaces coexistence** is the modern Nx default; Nx infers/wraps package
  manager workspaces. This preserves pilot compatibility (pilot = npm workspaces) so S0.2's
  BC migration is close to copy-paste.
- **Nx chose over npm-workspaces-only** (user decision): buys the task graph, caching,
  affected-only builds (useful for ADR-012 path-aware CI) and native module boundaries, at
  the cost of new tooling in the devcontainer.

## Verification

1. `npm install` at the root resolves `apps/*`, `libs/*`, `services/*`, `infra/*`, `mockups`.
2. `npm run build` → `nx run-many -t build` exits 0 across the four placeholders.
3. `npm run test` → `nx run-many -t test` exits 0 (four trivial tests pass).
4. `npm run lint` → `nx run-many -t lint` exits 0.
5. `npm run mockups` serves the mockups on `:5173`; the mockups' own `vitest` suite still
   passes from inside `mockups/`.
6. `nx graph` shows four tagged placeholder projects and enforces boundaries.
